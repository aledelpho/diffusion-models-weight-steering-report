| **45** | Assuming a permuted control inherits the target displacement | `BLOCKSHUFFLE` is built from the same multiset of gains as the preset, so its displacement was assumed to be identical by construction — as it genuinely is for `RANDSIGN`, where every gain keeps its own tensor and only the sign changes | It is not identical for a permutation. Deranging which block group receives which gain changes *which norms are multiplied by which numbers*, and on Anima the shuffled variant landed at $D = 0.044077$ against a target of $0.045745$ — **3.6% low**. Small, and in exactly the direction that would make the structured control look weaker than the preset, which is the comparison the whole "structure, not magnitude" argument rests on | Rescale **every** variant individually to the target $D$ after construction and print the achieved value for each one. A matched control that is not matched is not a control, and a 3.6% dose gap gets read as a structural difference |
| **46** | Baking an edit into a bf16 checkpoint without checking it survives the quantisation | Applying a preset offline and writing the result back to a bf16 file is arithmetically the same operation the tuner performs at runtime, so it was treated as equivalent | It is not equivalent: the runtime path holds the patched weights at working precision, while baking rounds every element back to 8 mantissa bits. Measured on a synthetic checkpoint, the realised per-element gain deviates from the requested one by up to $3.9 \times 10^{-3}$ relative — exactly $2^{-8}$. At the gains used here ($0.02$–$0.11$) the edit is an order of magnitude above that floor and survives cleanly, but a gain of $0.001$ would be **swallowed whole** by the rounding, and a sweep of small doses baked this way would show a floor that belongs to the file format rather than to the model | Before baking, compute the ratio between the smallest gain in the preset and the storage format's relative precision ($2^{-8}$ for bf16, $2^{-11}$ for fp16, $2^{-24}$ for fp32). Below roughly 10:1, bake in fp32 or apply at runtime. Always round to nearest even, never truncate: truncation biases every one of hundreds of tensors toward zero in the same direction |
