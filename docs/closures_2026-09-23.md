## 3. CLIP: the reason was wrong, the question is still open.

Page 01 argued CLIP at 224x224 cannot see the mark-style shift because the resample destroys the
stroke detail. That argument needs no encoder to test, and
`experiments/measure_downsample_blindness.py` tested it: 16 stage-7 prompts, preset against
block shuffle, this repository's own features computed on the render as saved and again after
CLIP's exact preprocessing.

**The separation survives the resample.** Ten of eleven statistics keep at least half their
paired effect size at 224 and five grow; `lbp_entropy` keeps 92% and stays significant
(p = 0.0006); stroke-width dispersion becomes significant only after the resample, which is what
aliasing a fine periodic texture does. The claim stays open, but for a different reason:
blindness, if it exists, would have to come from the encoder's learned representation, not from
its input size.

`experiments/measure_clip_distance.py` measures that, on `clip_vision_h.safetensors`, which is
already on this machine. It has not been run: no CLIP weights are reachable from where this
analysis ran, and the file is 1.2 GB. It reports the within-prompt distance as a fraction of the
across-prompt distance, because a raw cosine on its own says nothing.

## 4. The sensitivity curve: the same angle is not the same dose.

Page 10 rotates all six block groups by the same number of degrees, which is not the same
perturbation: `D = ||dW||/||W||` scales with the rotated group's own norm.
`data/matched_rotation_calibration_v4.json` settles it for the two ends — B6 needs a larger
angle than B1 to reach the same D, and the ratio is constant to five figures across three doses
— so at a common angle **B6 receives only 0.740 of B1's displacement**.

Correcting for it widens the gap instead of closing it: B6 against B1 goes from 5.35 / 4.16 /
4.13 as rendered to **7.23 / 5.62 / 5.58** per unit of displacement. The advantage is largest at
the smallest angle and flattens from mid to high, which is what saturation at the output end
would look like; three angles cannot tell saturation from noise.

`experiments/sensitivity_curve.py` writes `data/sensitivity_by_block.csv`.
`experiments/measure_block_group_displacements.py` fills in B2 to B5 by reading the checkpoint —
no renders — and will also settle whether this bench's B6 is blocks 23-27 or the tuner's 24-27,
which the normalisation currently assumes.

## Reproducing all of it

`experiments/reproduce_2026-09-23.py` re-runs every measurement above from the renders and
checks that each one lands back on the file that is committed. It writes nothing into `data/`
by default: each phase recomputes into `data/_repro/` and the result is compared cell by cell
against the committed CSV, numeric cells within tolerance and string cells exactly. No expected
value is typed into the script — what each phase is checked against is the repository's own
file, so it cannot certify a number by agreeing with itself.

    python experiments/reproduce_2026-09-23.py --list
    python experiments/reproduce_2026-09-23.py
    python experiments/reproduce_2026-09-23.py --only noise_floor
    python experiments/reproduce_2026-09-23.py --images-root "D:/wherever/the/renders/are"
    python experiments/reproduce_2026-09-23.py --write        # overwrite data/, no comparison

Seven phases: `corpus` (manifests only), `noise_floor` (38 baseline renders), `downsample`
(32 renders, slow — 64 feature extractions), `displacements` (the checkpoint), `sensitivity`
(data only), `figures` (the four charts whose data moved), `contract` (the validator, then the
build freshness check).

`displacements` is the one phase that has never run: it needs `torch` and ComfyUI's
`Arthemy_Krea2_Tuner` on the path. It is skipped with a message rather than failing the run,
and `sensitivity` then falls back to the two-block calibration, exactly as the committed file
did. When it does run for the first time it has nothing to compare against, says so, and
`data/sensitivity_by_block.csv` will change on purpose: B2 to B5 stop being `not measured`.

StabilityMatrix shows one copy of the outputs at two paths — `Data\Images\Text2Img\<bench>`
and `Data\Packages\ComfyUI\output\<bench>` — and both are tried, in that order.

Everything except `displacements` was run against the renders while this was written, and every
phase reproduces.
