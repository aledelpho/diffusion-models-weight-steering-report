| **71** | Designing a sweep over a tool from the architecture underneath it, while importing the tool | The perturbation atlas partitioned Krea-2 into thirteen regions enumerated from the checkpoint's tensor hierarchy (`docs/model_structures/krea2_turbo_bf16_details.json`): four depth bands of seven blocks × attention/mlp, plus `modulation_norm`, `txtfusion`, `clip_only`, `model_only`, `uniform_all`. Six amendments preceded the renders, each catching a real defect in the derivation, the anchoring or the plan. | `experiments/derive_atlas_presets.py` line 46 imports `Krea2TensorParser` — the class holding `MODEL_SURGEON_MAP`, the list of components the tool exposes and the same object the node iterates to build its widgets. `mod.lin` had been **removed** from that map during the node's development, with a comment on the spot recording that every sweep over it produced images byte-identical to the baseline. The atlas re-added it by hand as a pattern string and rendered it. Two consequences: 48 wasted renders, and a **false positive in the primary region analysis** — the region's two independent draws sit at distance exactly zero from each other by construction, which alone carried the apparent region effect from R = 0.391 (p = 0.278) to R = 0.833 (p = 0.159). The same root cause also gave the atlas 7-block quarters where the node offers 5-block groups and single blocks, so no atlas condition corresponds to anything a user can select. | **When the object of study is a tool, enumerate the tool's own exposed controls, not the architecture beneath it** — and assert it: every tensor of every region must be covered by some value of the tool's component map. Three lines at derivation time, fails on `mod.lin`, passes on everything else, costs nothing and runs before the first render. Then **keep the dead region and declare it the negative control**: an inert condition whose two draws must collapse to zero is the cheapest validation a sweep can carry, and a sweep that reports it as distinguishable has diagnosed itself.
